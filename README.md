# RMR Realty — Full-Stack Website

A complete, working full-stack website for RMR Realty: a public marketing site (Home, About, Projects,
Amenities, Gallery, Contact, Broker Registration, customer login) plus an admin panel (leads, brokers,
projects, content, chatbot conversations) and a zero-cost rules-based "Ask RMR" chatbot.

This README explains exactly how to run the project locally in VS Code. No source code editing is
required to start it.

---

## 1. Prerequisites

- **Node.js 18 or later** (this project was built and tested on Node 22). Check with:
  ```bash
  node --version
  ```
- npm (comes with Node)

No database server, Docker, or paid account is required. The database is a local SQLite file created
automatically the first time you run the setup commands below.

---

## 2. Project structure

```
rmr-realty/
├── backend/     # Express API + SQLite database
└── frontend/    # React + Vite + Tailwind website
```

You will run two terminals: one for the backend, one for the frontend.

---

## 3. Backend setup

Open a terminal in VS Code and run:

```bash
cd backend
npm install
cp .env.example .env
```

Now open the new `backend/.env` file and set a real admin password:

```
ADMIN_PASSWORD=choose_a_strong_password_here
```

(Optional but recommended) Generate real random values for `JWT_ACCESS_SECRET` and
`JWT_REFRESH_SECRET` — you can use this command and paste the output into `.env`:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Then set up and seed the database:

```bash
npm run db:migrate
npm run db:seed
```

`db:seed` creates your admin account (using the username/password from `.env`) and loads the verified
project content (Geetha Garden, Prestige Imperial, Royal Enclasa) and site text.

Start the backend:

```bash
npm run dev
```

You should see: `RMR Realty API listening on http://localhost:4000`

---

## 4. Frontend setup

Open a **second terminal** in VS Code:

```bash
cd frontend
npm install
npm run dev
```

You should see a local URL, typically `http://localhost:5173`. Open that in your browser — that's the
live website.

---

## 5. Logging in

**Customer login/register:** available from the "Login" button in the site header. No pre-made account
is required — use the Register page to create one.

**Admin panel:** go to `http://localhost:5173/admin/login` directly (this is intentionally not linked
from the public navigation). Use the username and password you set in `backend/.env`
(`ADMIN_USERNAME` / `ADMIN_PASSWORD`, default username is `ADMIN - RMR`).

---

## 6. Everyday commands

| Command | Where | What it does |
|---|---|---|
| `npm run dev` | backend | Start the API server (auto-restarts on file changes) |
| `npm run dev` | frontend | Start the website (hot reload) |
| `npm run build` | frontend | Build the production-ready static site into `frontend/dist` |
| `npm run preview` | frontend | Preview the production build locally |
| `npm run start` | backend | Start the API server without file-watching (for production) |
| `npm run db:migrate` | backend | (Re)create database tables — safe to re-run any time |
| `npm run db:seed` | backend | Reset admin account + reload verified project/content data |

---

## 7. Adding or changing project content

Two ways:

1. **Admin panel** (recommended for day-to-day edits): log in at `/admin/login`, then use the
   **Projects** and **Content** tabs to edit text, mark a project as "verified" (which switches it from
   the honest "coming soon" layout to the full project page), or update the About Us / Vision / Mission
   text.
2. **Seed script**: for bulk changes or adding a brand-new project, edit
   `backend/src/db/seed.js` and re-run `npm run db:seed`.

## 8. Adding project photos/media

Drop image files into:
```
frontend/public/media/projects/{project-slug}/
```
Then either add matching rows via the admin panel (future enhancement) or update the `mediaCount` /
file naming in `backend/src/db/seed.js` and re-run `npm run db:seed`. Keep images under ~300KB each for
fast page loads — resize/compress before adding if needed.

## 9. Adding the final cinematic video(s)

Per the project decision, cinematic AI video is being produced separately by your team and is **not**
generated by this codebase. When a final video file/URL is ready:

1. Log in to the admin panel → **Projects** → edit the relevant project → paste the video URL into the
   "Video URL" field → Save.
2. That's the entire integration step. The branded fallback panel is automatically replaced by the real
   video player — no code or design changes needed.

## 10. Multilingual content

UI text (navigation, buttons, form labels) is translated into English, Tamil, Telugu, and Kannada in:
```
frontend/src/i18n/locales/{en,ta,te,kn}.json
```
Client-specific business content (About Us paragraphs, project descriptions) intentionally stays in
English until official translations are supplied — this avoids publishing machine-translated business
claims. To add official translations later, extend the `ContentBlock` model / admin Content editor with
per-language values.

## 11. Deployment

This project is deployment-agnostic. For a typical zero-cost deployment:
- **Frontend**: run `npm run build` in `frontend/`, then deploy the `frontend/dist` folder to any static
  host (e.g. Vercel, Netlify — both have free tiers).
- **Backend**: deploy `backend/` to any Node-capable host with persistent disk for the SQLite file (e.g.
  Render, Railway free tiers). Set the same environment variables from `.env` in your host's dashboard —
  never commit `.env` itself.
- Update `FRONTEND_ORIGIN` in the backend's environment to your real frontend domain, and update the
  frontend's API base URL/proxy if the backend is on a different domain.

A specific hosting recommendation was intentionally left open per the requirements document
("Hosting Plan Preference: To be recommended by Service Provider") — happy to advise once you're ready.

## 12. Email notifications (new — one credential needed from you)

Contact/project leads and broker registrations always save to the database and show up in the
admin panel, exactly as before. On top of that, the site can now **also** email the company the
moment one of those forms is submitted.

This is off by default and safe to leave off — nothing breaks without it, the mailer just logs a
one-line warning and skips sending. To turn it on:

1. Open `backend/.env`.
2. Get a free Gmail **App Password** (this is not your normal Gmail password):
   - Go to <https://myaccount.google.com/security>
   - Turn on 2-Step Verification if it isn't already on
   - Search for "App passwords", create one for "Mail"
   - Google gives you a 16-character code
3. Paste that code into `SMTP_PASS` in `backend/.env`. The other `SMTP_*` values are already
   filled in for `rmrrealty.official@gmail.com` — change `SMTP_USER`/`NOTIFY_TO` if you'd rather
   use a different mailbox.
4. Restart the backend (`npm run dev`). Submitting the Contact form or Broker Registration form
   will now also send a real email, in addition to saving to the database.

No paid email API is used — this is Nodemailer (free, open-source) talking to Gmail's free SMTP
service.

## 13. Visitor & search tracking (new)

The site now records two more kinds of activity, purely for the admin panel — no third-party
analytics service, zero cost:

- **Page views**: every public page load is logged anonymously (path, referrer, a random
  browser-generated visitor id — no personal data). Admin panel visits are excluded.
- **Searches**: the new search box on the Projects page (search by project name or location) logs
  what people search for.

View both under **Admin → Visitors**, and see rolled-up counts on **Admin → Dashboard**.

## 14. Known limitations (honest, not hidden)

- The Google Maps embed on the Contact page is a free `<iframe>` embed (no billed API key). It was
  tested working; if it fails to load in your environment, check that your network allows
  `maps.google.com`.
- `react-router-dom` has one open moderate-severity advisory with no non-breaking patch available yet
  (GHSA-wrjc-x8rr-h8h6) — the app never passes untrusted input into navigation, so real-world exposure
  is low, but upgrading to `react-router-dom` v7 in the future is worth planning for.
- Royal Enclasa intentionally has no location/pricing/amenities content yet — see Section 7 above for
  how to publish it once verified details are supplied.
- Email notifications require the one Gmail App Password step in Section 12 above — until that's
  added, forms keep working (save to DB + show in admin), they just don't also send an email yet.
